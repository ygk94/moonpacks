# Moonpacks web app

The Moonpacks front end: buy memecoin card packs, open them with an on-chain reveal, and trade or burn the cards.
**NEAR testnet only** (the app refuses to start on any other network).

- Live app: https://moonpacks-ochre.vercel.app
- Contract: `app4.simpletea5483.testnet`

## Features

- **Shop**: Classic packs, Full Moon packs and themed packs. Each pack links to its published odds.
- **One-click opening**: "Open pack" sends the purchase straight to the wallet, which shows the exact amount to sign.
  The opening animation starts at signature; the app then polls `get_pack` and reveals the cards one by one as soon
  as the on-chain draw lands, with effects scaled to rarity. A stalled draw can be retried by the buyer, and a stuck
  pack can be refunded.
- **Collection**: your cards and your past packs (any opening can be replayed, also via `#/open?pack=N`).
- **Burn**: redeem a card from its detail view; the freed storage deposit is returned.
- **Market**: list, delist and buy cards. Buying shows a summary with the exact price, the royalties (`nft_payout`,
  NEP-199) and the seller's share before signing.
- **Transparency** (`#/rates`): odds per series and pack type, the table hash and the deployed code hash.
  "Verify this pack" recomputes any draw **in the browser** (`src/verify/`, a port of `../verifier/`): table hash,
  seed chain, rarity roll and fallback of each slot, card choice and value tier. With the indexer's history, the
  whole series is replayed from its opening for an exact check of every card.
- Mythic cards are sealed: they are always shown face down ("?"). No mythic name or file is ever served;
  `scripts/check-mythics.mjs` enforces this after every build and in `npm test`.
- No profitability figures, no fake urgency: only token amounts and public prices are shown.

## Stack

Vite, React 19, TypeScript, Framer Motion (opening animation), plain CSS. Wallets via
`@hot-labs/near-connect` (MetaMask through the "Ethereum Wallets"
connector is listed first; WalletConnect is optional). A tiny hash router (`#/shop`, `#/collection`, `#/market`,
`#/rates`, `#/legal`); no state library.

| Folder | Content |
|---|---|
| `src/near/` | RPC, typed contract reads, NEP-297 events, wallet, contract error translation |
| `src/lib/` | Formatting, public prices (CoinGecko, DexScreener), catalog, pack logic, market helpers |
| `src/verify/` | In-browser draw verification and full series replay |
| `src/components/` | Card, pack art, header and banner, modal, card detail (burn, listing) |
| `src/pages/` | Home, Shop, Opening, Collection, Market, Transparency, Legal |
| `indexer/` | Optional read-only event indexer |
| `scripts/` | Asset preparation, checks, smoke and end-to-end runs, deployment |

## Run locally

Requires Node 20+ and Python 3 (card art is generated by `../art/`). From `front/`:

```sh
npm install
npm run dev        # http://127.0.0.1:5173
```

To target the current deployment, set the contract first:

```sh
VITE_CONTRACT_ID=app4.simpletea5483.testnet npm run dev
```

Vite listens on `127.0.0.1` only; `DEV_HOST=0.0.0.0 npm run dev` opens it to the local network (e.g. a phone).

## Scripts

| Command | What it does |
|---|---|
| `npm run prepare-assets` | Writes `public/catalog.json` (public card data from `../docs/data/`, mythics excluded) and `public/cards/*.svg` (rendered by `../art/`). Only regenerates when the catalog or `art/` changed. Run automatically by `dev` and `build`; the output is git-ignored |
| `npm run dev` | `prepare-assets`, then the Vite dev server |
| `npm test` | Vitest suite, then the mythic leak check |
| `npm run build` | `prepare-assets`, type check, production build in `dist/`, then checks that the test wallet and any mythic data are absent from the build |
| `npm run deploy` | `build`, then `scripts/deploy.mjs`: copies `dist/` to `.deploy/moonpacks/` and runs `vercel deploy --prod` (`node scripts/deploy.mjs --preview` for a preview URL) |
| `npm run typecheck` | `tsc -b` only |
| `npm run indexer` | Starts the optional indexer (see below) |
| `npm run smoke` | Read-only browser walkthrough (Playwright, headless Chromium) against a running `npm run dev`; screenshots in `smoke-captures/` |
| `npm run e2e` | Wallet flows (buy, burn, market) with real testnet transactions signed by local test accounts; dev-only key wallet, never part of a production build |

Playwright needs a browser once: `npx playwright install chromium-headless-shell`.

## Configuration

All variables are optional and documented in `.env.example` (copy it to `.env.local`). No API key is needed.
Defaults come from `src/config.ts`.

| Variable | Default | Purpose |
|---|---|---|
| `VITE_NETWORK` | `testnet` | Only `testnet` is accepted |
| `VITE_CONTRACT_ID` | `app4.simpletea5483.testnet` | Contract to read and call |
| `VITE_RPC_URL` | `https://rpc.testnet.fastnear.com` | NEAR RPC endpoint |
| `VITE_SERIES_ID` | `0` | Default series |
| `VITE_BLOCK_TIME_S` | `0.6` | Average block time, used for gold rush countdowns |
| `VITE_INDEXER_URL` | `http://127.0.0.1:8787` in dev, empty in production | Indexer base URL; empty disables it |
| `VITE_WALLETCONNECT_PROJECT_ID` | empty | Enables WalletConnect (free project id at cloud.reown.com) |
| `VITE_CONTACT_EMAIL` | empty | Contact address shown on the legal page |

`DEV_HOST` is a shell variable read by `vite.config.ts`, not a front-end variable.

## Indexer (optional)

In a second terminal, from `front/`:

```sh
npm run indexer
```

`indexer/indexer.mjs` is a small Node service (built-in `node:sqlite`, no dependency). It pulls the contract's
transactions from the FastNEAR transactions API, stores the NEP-297 events in `indexer/data/` (git-ignored), and
serves a read-only API on `127.0.0.1:8787`: `/status`, `/trending?hours=24`, `/sales`, `/history?series_id=N`
(events needed to replay a series), `/resurrected` and `/events?event=…`. A transaction is only read once it is
20 blocks old, when its draw is complete.

| Variable | Default |
|---|---|
| `INDEXER_CONTRACT_ID` | `VITE_CONTRACT_ID`, else `app4.simpletea5483.testnet` |
| `INDEXER_RPC_URL` | `VITE_RPC_URL`, else `https://rpc.testnet.fastnear.com` |
| `INDEXER_TX_API` | `https://tx.test.fastnear.com` |
| `INDEXER_HOST` / `INDEXER_PORT` | `127.0.0.1` / `8787` |
| `INDEXER_POLL_MS` | `3000` |
| `INDEXER_DB` | `indexer/data/<contract>.sqlite` |

Without the indexer, "Trending" falls back to the contract's current listings, and full series replay is left to
the command-line verifier (`../verifier/`).

## Deployment

The site is static (hash routing, no rewrites); `public/vercel.json` sets caching headers. The indexer is not
deployed.

`.github/workflows/ci.yml` runs on every push and pull request: front tests and build, Python tests (`art/`,
`verifier/`, `sim/`) and contract unit tests. On `main` (or on a manual run with the "deploy" box checked), it then
runs `npm run deploy` with the repository secrets `VERCEL_TOKEN`, `VERCEL_ORG_ID` and `VERCEL_PROJECT_ID`, and the
repository variable `CONTRACT_ID` passed as `VITE_CONTRACT_ID`.

To deploy by hand: `npx vercel login` once, then `npm run deploy`.
